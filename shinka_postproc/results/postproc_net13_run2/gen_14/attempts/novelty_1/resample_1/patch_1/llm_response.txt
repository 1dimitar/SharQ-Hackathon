<DESCRIPTION>
Adapt the number of LP evaluations per neighborhood to both search stagnation and surrogate ambiguity. The current fixed batch of nine can undersample a neighborhood when the parent has repeatedly failed to improve, or when many candidate moves have nearly tied surrogate scores and their ranking is unreliable. Keep small batches for clearly ranked moves, but expand them progressively for stalled parents and close-ranked neighborhoods, up to 24. This spends the existing LP budget on more informative comparisons where the surrogate is least decisive, without changing move generation or exceeding the budget.

    def screen_batch(moves, parent, batch_size=9):
        """Adapt LP batch size to neighborhood ambiguity and parent stagnation."""
        fresh = [
            m for m in moves
            if m not in seen and not tools.is_cached(m)
        ]
        if not fresh:
            return []

        base_e = energy(parent)
        ranked = sorted(
            ((energy(net) - base_e, net) for net in fresh),
            key=lambda item: item[0],
        )

        # A close cluster of leading surrogate scores is weak evidence for
        # preferring one move, so use more LP calls to compare that cluster.
        if len(ranked) >= 8:
            top_values = [value for value, _ in ranked[:8]]
            spread = max(top_values) - min(top_values)
            scale = max(1.0, abs(base_e), abs(top_values[0]))
            if spread <= 0.02 * scale:
                batch_size = 18

        stalls = parent_stalls.get(parent, 0)
        if stalls >= 4:
            batch_size = max(batch_size, 14)
        if stalls >= 9:
            batch_size = max(batch_size, 22)
        batch_size = min(batch_size, 24)
