# INDIVIDUAL PROGRAM SUMMARIES

The following are summaries of individual programs evaluated since the last meta update:

**Program Name: Pressure-Discounted Two-Hop QUBO Surrogate**
- **Implementation**: Normalizes nonnegative, non-self demand and assigns negative linear weights using a demand/square-root blend. For each positive-demand pair, it selects a small set of two-hop routes by pressure-adjusted affinity, adds a low-pressure alternative, and returns a fixed penalty weight of 1.25.
- **Performance**: Combined score is 0.89 (raw 0.83, post-processed 0.96); mean best and median gaps are 11.66% and 32.42%, with 91% feasibility and 383 quadratic terms on average.
- **Feedback**: The surrogate builds quickly and produces consistently strong post-processed results, reducing the mean gap to 4.38%. Before repair, median gaps remain around 29–37%, and the largest best-sample gap is 16.8% for network14_s0, so its strongest contribution is as a head start for the fixed post-processor.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Tune neighbor-service coupling strength while keeping its selection budget fixed.** Retain the current service profiles, `service_budget = max(1, n // 2)`, and all route and cut terms, but sweep the `0.24` multiplier over approximately `0.18`, `0.21`, `0.27`, and `0.30`. Service-aware factors distinguish the strongest design from weaker route/cut-only variants, so an isolated strength sweep could improve raw sample rankings without sacrificing repaired quality.

2. **Vary service-interaction sparsity independently of strength.** With the current `service_strength` unchanged, test budgets near half and 1.5 times the current value, such as `max(1, n // 4)` and `max(1, 3 * n // 4)`. This checks whether the current top-gain pair selection is pruning useful complementary coverage or adding noisy interactions; sparse models have matched richer models’ scores, so judge the variants by both repaired gap and raw score.

3. **Improve route-candidate ranking using endpoint pressure, without broadly increasing the number of routes.** Keep the two-route default and existing third-route ambiguity rule, but blend modest source and target pressure into the candidate rank, for example by multiplying its current score by a clipped factor derived from `pressure[i]` and `pressure[k]`. The best program benefits from supported, bounded routes, while the poorer results of narrow candidate limits warn against simply cutting alternatives further.

4. **Test a gentler size dependence for the route and service rewards.** Change only one scaling rule per run—for example, narrow the route factor’s upper range or reduce the logarithmic size multiplier in `service_strength`—and compare results particularly at sizes 15–16, where raw quality and head-start quality decline. Preserve the current factor composition while checking whether its size adjustments over- or underweight these rewards on larger networks.

5. **Sweep the cut correction’s magnitude while preserving its normalized construction.** Vary `cut_strength` around `0.80 / 144.0` (for example, test 0.65 and 0.95 times the current value), leaving the load normalization, endpoint vulnerability, and offset removal unchanged. Cut corrections complement service and route factors in the strongest designs; an isolated scale test can reveal whether they help the larger instances without confounding changes to their structure.
